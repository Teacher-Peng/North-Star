# 題庫品質關卡

已從面積擴大到五年級上學期全部 10 單元、234 題（原 218 題，另補 16 題課綱代表題）。每單元各有同名 JSON 履歷；總報告為 `GRADE5_REPORT.md`。獨立重算的答案與理由在 `review-basis.json`；面積沿用 `area.json` 原有案例。範圍不含五下。

## 日常操作

- `npm run quality`：檢查全部五上題目資料與履歷、正反判分案例、圖解標示、AI context，以及單元集中度。更新報告，有阻擋問題時 exit 1。
- `npm run verify`：先跑回歸測試，再跑品質檢查。內容或判分變更應執行此命令。
- `npm run quality:release`：嚴格試用關卡。除了程式通過，必須有目前版本的教學審查、視覺／操作審查與人工確認；缺少任何一項 exit 1。這是本機檢查命令，尚未接入部署或隱藏既有原型題目。
- `npm run quality:packet`：產出 `GRADE5_REVIEW_PACKET.md`，提供逐題內容、教學目標、檢查項目與版本指紋，供另一位審查者使用。不呼叫模型、不使用付費 API、不自動核准。

## 每題履歷

`id` 對應題庫 ID；`revision` 是內容版本；`fingerprint` 綁定題目、教學目標與檢查條件等履歷內容，以及共用畫面／判分／AI context 程式。任何相關變更使舊紀錄過期，需要重新檢查；不能只更新指紋就聲稱通過審查。

`curriculum`、`objective`、`prerequisites`、`thinking`、`interaction`、`difficulty`、`misconception`、`scaffolding`、`grading` 說明教學設計。`cases` 用人工推導的正反例驗證實際判分器，不從題庫 answer 複製生成答案；`facts` 指定圖上和題目應一致的數值，`renderLabels` 指定 SVG 應呈現的標示。兩者只能驗證列出的條件，無法理解任意自然語言或圖片的所有矛盾。

`reviews` 分為 pedagogical、visual、human、child；每筆均需要 status、reviewer、method、date、fingerprint、evidence。初始 pending，不偽造實測。人工確認必須由真人留下具體證據，AI 不得代簽；孩子不必留下姓名、影像或其他個資。`findings` 保留具體理由、嚴重度、修正與狀態。

## 狀態與放行

- 草稿：履歷缺漏或數學、判分、圖文等阻擋問題。
- 待審：程式通過，但教學／視覺／人工證據缺少、過期，或仍有開放的重要問題。
- 可試用：上述審查通過，且目前版本由真人確認；還沒有孩子實測。
- 已驗證：可試用基礎上，加上孩子操作觀察證據。這只代表該版本的有限試用，不等於所有小五學生都適用。

答案錯、資料不足、圖文矛盾、判分排斥合理答案是 blocker。教學目標不符、提示洩題、先備知識跳躍是 major；blocker / major 未解決都不能放行。文字長度、認知策略與互動集中度是 warning，需人閱讀判斷；不能用總分平均抵銷重要問題。

## 審查者工作順序

1. 不先看標準答案，自己解題；確認是否足夠、唯一或允許多解。
2. 比對課綱、先備能力、讀題負擔與錯誤選項的教學意義。
3. 看初始畫面、答錯、提示、答對四種狀態；用滑鼠／鍵盤檢查，iPad 另外實測。
4. 審整個單元的概念覆蓋、難度順序及重複策略，不能只逐題打勾。
5. 在 reviews 寫具體觀察；有問題記入 findings，修正後重跑檢查及受影響的審查。

目前的初步教學意見由同一開發助理另輪檢視，**不是獨立 AI 審查或真人教育者認證**。另一位 AI 可使用 review packet 提供意見，但不能填 human 通過，也不能靠自己的意見直接發布。

## 試用觀察表

記錄題目 ID／版本、裝置、孩子怎麼理解任務、卡在數學還是操作、用了什麼提示、修改建議。先讓孩子說明「這題要做什麼」，再操作，不先示範答案。只記答對率無法判斷理解；個別觀察不代表一般化有效性。
